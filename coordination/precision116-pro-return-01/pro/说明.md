# 本轮交付说明

本轮交付的是可按顺序应用的 **RED/GREEN 代码草案**，不是已经编译通过的实现。RED 只增加一个实验测试入口和独立 CTest；它直接调用尚不存在的新工厂，交给集成负责人先取得真实的“缺少工厂 API”编译失败记录。GREEN 再增加 `CreateExperimentalPrecision116Setup()`，只修改指定的四个生产文件，不改 RED 断言。

新配置固定为 `experimental-s116-d56-b58-v1`：两个基底模数和除数使用候选中的精确常量，其余八个模数及保留 P 不变。基础元数据从 50 位调整到 58 位，新鲜密文和 RS 的记录尺度为 2^116；真实逻辑尺度仍按精确有理数递推，不能拿记录尺度替代。原工厂仍发行原参数，原来的诊断型客户端仍只接受原 S100 路径。

这可能改善新鲜误差预算，但目前只有条件性的静态分析，尚未测量新参数的实际编码误差和噪声。提高尺度和除数，不意味着所有误差都自动下降固定倍数。新测试只做一次公开加密、DCP 和一次 Mult2，检查八个上下文、密钥归属、尺度收据、family1 重入和释放清理；不会跑八次平方，也不会放宽只允许终态调用的接口。

本次实际完成了输入与清单核验、补丁顺序应用、旧代码保护、常量与九个精确尺度核对。原有七项纯标量测试通过，两个编译器只检查了常量描述符片段。**项目未编译，密码运算未运行，实验测试未运行。** 原 E80 失败保持失败；新配置安全性仍未解决，也没有获得生产采用或独立审查通过。

下一步必须先在托管环境取得 RED 编译记录，再应用 GREEN，完成 Linux/Windows 无警告构建、新的一次运算测试及原有检查，最后由独立人员审查。旧 57/60 检查要排除新增实验测试，并跳过旧的无参数八平方实验。完整八平方数值验证属于后续另行授权的任务。
