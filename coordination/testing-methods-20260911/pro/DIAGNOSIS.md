## 测试实际回答什么

在一个使用原生随机源、现有 h128 公共夹具的进程中，检查：公开整数导入与实际 EV 坐标；secret 的 h128/跨塔一致；`pk0+pk1*s` 的全部系数；同一密文 `c0+c1*s-p` 的全部系数；公开 Poly* 解密与独立唯一整数提升的精确一致。独立读取不调用 OpenFHE 的 INTT、CRTInterpolate、DecryptCore 或高精度客户端编码器。秘密仅用于客户端诊断进程内运算。[S02–S07；数学推导见 TEST_PLAN]

两个负对照都是**错误输出注入**，不是生产修复，也不是 mutating oracle：只给一个 CRT 塔的 c0 加常数 1，必须触发跨塔不一致；给所有塔加同一个常数 30031，必须跨塔一致但超过支持界。这样不会让“只检查形状”“忽略密文”“始终返回零误差”的空测试蒙混过关。构建失败、普通异常或超时不能被计作捕获数值故障。

## 为什么不跑 paperN

N64 放不下 h128；N256 是**现有代码已经使用的 h128 夹具**，不是宣称数学上的最小维度。它保持真实客户端 adapter、同一 PKE 分支与 native64/backend4，容纳 100 位以上有符号明文，并让完全独立的 O(N²) 求值可用于所有系数。生成一套 key、一次 payload，加两个值副本，不生成 eval key，不执行 Mult2。[S03,S04]

本测试对这类基础表示/相位错误有判别力；不对 N32768 专有问题、11 塔形状、历史缓存时期、并行路径、最终舍入或 E80 做外推。清楚保留这个限制，比用共享同一个官方 INTT 的大测试宣称“完全独立”更可靠。

## 历史问题的精确观察缺口

原 run34039088536 的 Linux≈9.14647e-24、Windows≈9.06531e-24 对 T=2^-80 的 FAIL 原样保留。S116 改参 PASS、annulus 改输入/新 key/noise 的一次 PASS、当前 32768 个 p 系数证书，都不改写这个结论。[S11,S13；本次 TASK 的冻结事实]

附件给出历史聚合残差和当前源码，**没有给出可在同一客户端进程中关联到原 run 的完整初始密文、该次密钥及原始编码整数的现场对象**。不凭十个槽的聚合记录反求它们，不发明“历史 p 已相同”的证明，也不要求把私钥补传成文件。因此无法给本测试的当前 PASS 加上“已认证原历史相位”的含义。

若要供给同 profile 的下一次现场观察，最小安全形式是在现有 `s100_fresh_error_diagnostic_test.cpp:594–623` 已持有 inspection、source 和 rootSecret 时，进程内计算初始化不变量，只输出布尔结果与运行身份；不能输出相位向量、pk 噪声向量或可重建的 capture。它仍是新样本，不能重建历史。这里仅说明精确缺项与安全补给位置，**不把这个 paperN 观察另行派发为第二轮实验**。所附唯一新测试先回答 N256 的有界问题；完成后停止。
