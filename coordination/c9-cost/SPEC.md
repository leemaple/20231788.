# C9 complete-call feasibility probe

Bounded source preparation; no performance result and no formal study admission.
Base181fa5b has Intel native functional witnesses for Reference/SharedStaged/TailDigit/TailWide, repeated semantics, rejection and Wide-disabled fallback. Its CI packaging failed at lipo argument order; preserved binaries independently match their receipts and both architecture slices. This work changes no arithmetic, metadata, keys or tests.

## Scientific question and boundary

Does either tail schedule improve the complete public legacy Mult2WithBackend call beyond the strong SharedStaged baseline after all per-call preparation and both key switches? Reference is also reported. Formula and mixed-radix novelty are explicitly not claimed. This pilot filters whether more evaluation is worthwhile; it does not establish novelty or publishable results.

The first filter is legacy HYBRID with empty metadata and no repeated receipt, warm inputs on one later-fixed host. It does not measure family dispatch, Reenter, repeated chains, nonempty metadata, BV, peak memory, sparse-key security or originalS100/E80. These remain separate if the first filter is promising. Local kernels are deliberately deferred: a complete-call null result is already discriminating.

## Frozen future shapes and samples

--check: N64/depth3, scaling30/first35, HEStd_NotSet, HYBRID/digit0, no timing samples; one setup, four exact routes and two deliberate output-comparator corruptions (coefficient and slots).

--study: three independent profiles N16384/depth3, N32768/depth3, N32768/depth5; scaling58/first60, FIXEDMANUAL, requested HEStd_128_classic, default uniform ternary, HYBRID/digit0, slotsN/2. Actual Q/P/roots, divisor and survivor count are recorded. Security selection is not independent certification. Keys/encryption use unseeded upstream randomness and are shared among all routes within each profile, not treated as scientific repetitions or parameter retries.

Each profile has one Reference expected output and one untimed warmup/check per backend. Eight predeclared orders place each backend in each position twice; each order repeats three times, giving96 timed calls/profile and288 total. All input values follow deterministic small complex patterns; upstream encryption/key randomness is retained as a limitation. No adaptive trial counts, replacement shapes, fallback counted as requested execution, or silent reruns.

## Timing and equality

Time immediately before entering Mult2WithBackend and immediately after return, with the same trace pointer for every backend. The legacy branch includes Tensor, two key switches, checks/preparation/inverses/allocation, output metadata and final validation as actually implemented. Returned results remain alive until checks/logging finish; their final destruction, comparison, input checks and output IO are outside every timer equally. No candidate-only setup cache is introduced. Record steady-clock wall nanoseconds and process CPU nanoseconds separately; setup_and_checks includes context/key/encryption, Reference/control/warmup and public input/shape IO and is not attributed to an individual backend.

Every operation checks exact output coefficients, polynomial parameters, ciphertext and pair metadata against the same expected Reference, and requires trace.completed/requested/executed with fallbackNone. Input coefficients are copied into plain uint64 values; parameter/scalar states are copied into text, avoiding shared-Params snapshots hiding changes. Each timed call is followed by equality and input-immutability checks. Legacy empty maps/no receipt are a tested scope condition, not a comparator for future repeated benchmarks.

Only public pair coefficient bytes and public Q/P/roots are saved; no secret/evaluation key is written. These bytes bind paired inputs but are not a full replay package for identical key-switch randomness. Exact source/binary/environment/run/admission and all raw sample rows must be bound by the later diagnostic controller.

## Evidence interface

Probe refuses an existing output directory. --study additionally requires a64-hex admission identity, which is a binding field, not authorization by itself. Outer dispatch must verify the registered plan before launch. started/completed, profile-shape/public-input files and records.jsonl are retained. A failed route/shape/comparison/write exits nonzero and preserves partial files; no completed success is written after failure.

The check-only wrapper uses the already witnessed native controller's invoke/cancellation engine unchanged. It checks exact source hashes, launches one --check child with120seconds, validates marker/exit, all4 routes, shape and0 samples, and saves binary/stream/output hashes with exact run/source. Ordinary cancellation and timeout kill/wait the direct process; SIGKILL/host loss/unwritable disk cannot promise a final receipt. Existing invoke engine control evidence is reused; new wrapper gets6 saved-output mock cases and no new native run during source preparation.

The new exact-tag CI builds only this probe with the same fixed static OpenFHE1.5.0 commit, Native64/backend4, OpenMP/nativeopt off, strict C++17, arm64+x86_64. It executes only --check on Intel, verifies both architecture slices with input-before-command lipo syntax and uploads producer hashes. It cannot invoke --study. All existing native criteria are preserved; only the CMake source binding changes with the added excluded benchmark target. No old native CI is rerun for the packaging correction.

## Decisions reserved for later admission

A separately registered diagnostic must specify the fixed host/observed load, wall deadline and kill/reap ownership, one-shot inventory, output limits, source/binary identities and analysis/decision thresholds before execution. Compare block medians and retain every backend/profile, including negative results. Small or unstable wins cannot pass G1 by relabeling them; wider repeated/precision coverage and nearest-prior reading are still required for any paper claim.
