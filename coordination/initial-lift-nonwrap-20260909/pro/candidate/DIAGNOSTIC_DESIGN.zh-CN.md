状态：**C++ 与任何变换均未运行**。这是 `PUBLIC-S100-ENCODER-CAP-01` 一个后继动作的紧密实现，不是 evaluator 生产修复。作者侧运行记录在 `../EXECUTION_LEDGER.md`。

## 1. 为什么不使用现成带 key 的 client setup

原 `InspectEncoding` 需要已验证的 client context；当前 repeated setup 会建立根秘密和 evaluation keys。为了只回答公开 p 的幅度，不应为取得这个对象而新抽样，也不能把秘密/参考值送入 evaluator。

候选保留 `ComputeEncoding` 原函数体、primary/check 精度与所有现有 guard，新增诊断命名空间函数 `InspectFixedS100PublicEncoding(values)`。它只建立值初始化的 `ContextBinding` 快照，填写该函数实际读取的 geometry/fullBasis；没有 crypto context、public key 或合法 plan。固定 `FreshEncodingSpec` 为 16384 槽及 2^100；`FreshExactScale` 在空 plan 分支返回 spec 的精确尺度。这里只利用私有实现值结构，不声称生成了合法 production binding/receipt，也不把它交给任何 evaluator。

shape 检查先于 `TransformTable` 构造，空输入负例不运行编码。有效 driver 唯一使用原测试头内的 `Inputs()` + `ClientInputs()`，不调用其理想八平方 oracle。原输入头是公开生成公式，不是秘密数据。

两份补丁依次应用：RED 添加声明、driver、默认禁用 target，但没有函数定义；GREEN 添加上述薄入口。四份完整文件与补丁内存重放逐字节核对。其余生产函数、原有测试和 CI 不改。

## 2. 公共数据与来源绑定

`initial-lift-public-encoding-v1` 严格拒绝未知/缺失/重复字段，冻结 geometry、S、q/root、基点、profile、编码次数1/密码学次数0。系数必须是无前导零的十进制字符串，不能为 `-0`，恰32768项，并满足原 full-basis 中心范围 guard。单字符串≤200字符，输入文件≤12 MB，UTF-8 LF、完整换行结尾。

系数 p 是仅由公开输入和确定性编码数值过程产生的**公开消息多项式**，不是 `p+f`、DCP 相位或解密结果。临时文件可交独立复核者；最终聚合证书不会包含任何秘密状态。所谓 `crypto_calls=0` 仍需根端源码/运行路径审查支持，不能把输入 JSON 自报计数当执行证明。

driver 写入 base commit、实际构建 commit、Boost 版本和 `__VERSION__`；构建 commit 由原 CMake 机制读取。JSON 解析器拒绝 `unknown`，但无法证明标签真实；hash/路径/工具链/依赖由独立根端回执认证。文件存在时拒绝覆盖，能降低误覆盖风险，但不是并发原子 single-shot 计数器，也不是隔离边界。中途失败产生的不完整 JSON 会被解析拒绝；保留失败不自动重试。

在没有历史 p 或来源等价证据时，不自动把这次结果对应到旧样本。认证是关于其 hash 绑定的那个 p；无需历史私钥仍可推进当前源码定理。

## 3. 为什么再做独立区间正向运算

生产编码器“两精度相等/半距足够”不构成相对于精确逆嵌入的证明。此动作不重复证明正确舍入，只要认证实际整数 p 的 canonical 幅度就足以满足本文 K-CAP。其数值裕量约9.46e-4，不要求证明160位舍入的最后一位。

`certify_public_encoder.py` 用**独立的纯整数向外区间算术**直接包络所有 N 个奇 2N 次单位根值。包含共轭根，因此无需依赖生产 slot 排序、投影编号或低槽采样；p 为实系数，检查全部奇根等价于检查完整 canonical 最大模。

### 3.1 固定网格区间

令 U=2^224，区间 `[lo/U,hi/U]` 用两个任意精度 Python 整数表示。加减精确；乘法枚举四端点，将最小乘积向负无穷取整、最大乘积向正无穷取整后除 U；正整数除法同理。平方在跨零时下界取0，否则用两端较小平方。所有判断用整数交叉乘法，无 binary64 容差或近似日志决定通过。

使用常量区间时，Fraction → 网格转换也分别向下/向上。不存在“高精度所以视为精确”的隐含步骤。

### 3.2 π 与种子根的有理包络

对 q=5、239，使用 atan(1/q) 的96项交错级数与相邻下一项部分和包络。交错项单调递减，误差在相邻部分和之间。Machin 恒等式

`π=16 atan(1/5)−4 atan(1/239)`

可由 tan(2 atan(1/5))=5/12、tan(4 atan(1/5))=120/119，再用减角公式得到 tan(4 atan(1/5)−atan(1/239))=1；角位于第一象限，所以等于π/4。取下/上界时须注意减项方向。该标量 π 区间在作者侧已核包含于(3,22/7)，宽度≤2个网格单位；这不是 FFT。

种子角区间为π/N。对于|x|≤1，以cos的前32个非零项（到x^62）和sin的前32个非零项（到x^63）做区间多项式计算，并分别扩展 `|x|^64/64!`、`|x|^65/65!`。Taylor界可在零系数的63/64阶多项式上使用Lagrange余项，导数绝对值≤1。N≥4确保π/N<1。于是 seed 真包含 `exp(iπ/N)`。静态复核发现原16项版本的N=4余项不能保证未来2^-160宽度要求，因此在未运行变换时改为32项；补充标量断言确认最坏角上界11/14下两余项均小于2^-256。该修正是候选精度预算修正，不是生产算法bug或真实变换TDD结果。

### 3.3 完整 canonical 值

按区间复乘递推 seed 的0…N−1次幂，先把 p_j/S 乘以 seed^j。标准 bit-reversal + 正指数 radix2 DIT 计算

`sum_j (p_j/S) exp(π i j/N) exp(2π i j k/N) = p(exp((2k+1)π i/N))/S`。

每个阶段 twiddle 为 seed^(j·2N/length)，所用指数严格小于 N，根表长度充分。负号/实虚区间乘法保持包含。依赖导致的区间膨胀可能使结果不确定，但不会通过“中心化”缩小真实范围。

每个输出矩形转为模平方区间；取各下界最大值与各上界最大值，即可界定全体最大模平方。无需计算平方根。上界≤16129/16384认证K-CAP；下界大于它才否定K-CAP；否则不确定。

N=32768时，标准循环固定245760个蝶形、32767次根递推，另有32768次twist。每个标量整数规模受网格和输入系数上限约束；不会生成十亿位递推。作者侧没有执行这些循环。最终 JSON 记录 root seed、计数、区间宽度与精确分母，以便独立核验。
