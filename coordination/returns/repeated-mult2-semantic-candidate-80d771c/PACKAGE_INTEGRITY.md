# Package integrity and provenance

## Closure

The outer ZIP has one root `repeated-mult2-semantic-candidate-80d771c/` and regular nonempty payload files. `MANIFEST.tsv` lists every payload path, byte size, SHA-256, origin, source commit and implementation base. Its only self-exclusions are `MANIFEST.tsv` and `MANIFEST.sha256`; the latter authenticates the former. The external ZIP `.sha256` sidecar authenticates the finalized compressed archive and is not recursively included inside it.

`MANIFEST.tsv` paths are relative to the package root. The input's own authenticated manifest is retained byte-for-byte as `provenance/INPUT_MANIFEST.tsv`; its copied sidecar still names the **original** `MANIFEST.tsv` and is historical input provenance, not a command to check a renamed file in place. The offline verifier checks the original input archive directly.

Every delivered complete file must equal the result of applying RED then GREEN to the authenticated 40-file project baseline. `complete/project/` contains only the nine changed/new files. Both patches are ordinary Git unified patches rooted at the project directory, and no `.git` directory or fabricated source commit is included.

The new files, modified final files and patches have `source_commit=UNCOMMITTED` and the exact baseline in `base_commit`. This records derivation without falsely claiming that generated bytes existed in the baseline. Copied TASK provenance uses the later documentation-only overlay commit, never the implementation commit. Frozen vectors retain their prior archive origin and `source_commit=N/A` because no Git commit for that JSON is asserted. Generated review/verification documents are also uncommitted candidate artifacts.

## Independent checks and their limits

The stdlib-only verifier rechecks the original input ZIP/sidecar, its manifest and mandatory identities, all 53 official source payload identities, the expanded prior return's inner manifest, exact dyadic arithmetic and C++ transcription, ordered patch replay, complete-file closure, unchanged tests, all 58 source bindings, workflow preservation and bounded structural/kernel checks. It then checks all package payload bytes and self-exclusions.

`verification/STATIC_VALIDATION.json` is an actual observed offline run of the checks prior to manifest finalization. It is manifest-hashed as a fixed report. The final verifier is also run against the finalized package; that stdout and the outer ZIP inspection are not recursively embedded into the ZIP they authenticate. The external SHA-256 sidecar binds that finalized archive. These operations do not compile C++, run cryptography or execute hosted jobs.

The available packet contains expanded official and prior-return payloads, not their original standalone compressed ZIPs. Their compressed archive hashes are producer provenance only. No external Git fetch/show or source retrieval was performed. The provided bytes and provenance were checked; no unavailable parent archive or repository state is invented.

## Read/review scope

The current TASK, project workflow/reference documents, public seam and phase research, four dispositions, complete paper text, relevant matching PDF pages, current implementation/header/CMake/workflow and relevant baseline tests were read. The complete prior return was reviewed as evidence, including both tests/patches and its source ledger. The pinned official files supporting that ledger and this candidate were inspected at their cited APIs/algorithms, with all 53 official payloads additionally hash/blob-checked. A 53-file hash check is not a claim to have read every unrelated official source line. See the exact line ledger and input provenance copies.

No original input, upstream OpenFHE source, unrelated test, old assertion or frozen vector JSON was repaired in place. New diagnostic code is not imported from the old return. There is no credential/account/network use, push, merge, hosted dispatch or other-agent execution. This archive excludes `.git`, build trees, binaries, caches, credentials, private keys and machine state. The verifier's temporary scratch trees exist only during its offline replay.

The manifest and sidecar are integrity checks, not digital signatures or proof of independent runtime acceptance.
