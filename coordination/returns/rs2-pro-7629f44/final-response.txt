四、独立 centered-RS oracle

Oracle 不调用：

DoubleCKKS 私有 helper
OpenFHE Rescale
DropLastElementAndScale
生产 RS2

对每个输入 coefficient，使用 boost::multiprecision::cpp_int：

根据有序 RNS residues 做 textbook CRT；

将输入中心化到：

(-Q_l/2, Q_l/2]

取最后一个 active odd prime q_l，计算：

r = center(x mod q_l)
r ∈ (-q_l/2, q_l/2]

精确求商：

RS_q_l(x) = (x - r) / q_l

将有符号商独立转换回每个 retained modulus 的 residue。

分别计算：

expectedHigh       = RS_q_l(high)
expectedRecombined = RS_q_l(q_div*high + low)
expectedLow        = expectedRecombined - q_div*expectedHigh

检查范围覆盖：

2 个 pair members
× 2 个 RLWE components
× 全部 retained towers
× 全部 ring coefficients

并额外验证：

RCB_q_div(RS2(pair))
    == centered_RS_q_l(RCB_q_div(pair))
    mod Q_(l-1)
确定性边界

覆盖：

0
+1, -1
±(q_l-1)/2
±(q_l+1)/2
上述点的一步邻域
±Q_l/2 附近的可表示整数
正负交错的普通系数

所有模数均为奇数，因此没有虚构偶数模数的精确半点 tie。

两个关键 mutation witness

把 q_div 错当成 q_l：

使用：

(min(q_l, q_div) + 1) / 2

使按两个不同质数中心除法所得结果不同。

只做一次 RS 或错误使用 RS(low)：

设置：

high = (q_l + 1) / 2
recombined = 0

正确结果的 low 包含：

-q_div * RS(high)

它不等于 RS(low)。

测试还会动态确认这些 witness 在 retained composite modulus 下确实区分错误实现，而不是只假设它们有效。

五、精确状态与尺度公式

设输入 active basis 为：

[q0, ..., q_l]

active tower 数为 n，则：

q_l = input.GetOrderedModuli().back()
factorIndex = n - 1
f_recorded = parameters->GetModReduceFactor(factorIndex)

输出状态为：

basis_out = [q0, ..., q_(l-1)]
level_out = level_in + 1 = 2
degree_out = degree_in - 1 = 2
componentCount = 2
format = Evaluation
lifecycle = RefreshRequired
q_div 保持不变
context/tag/slots 保持不变

Recorded OpenFHE scale：

recordedSF_out = recordedSF_in / f_recorded

论文逻辑 high scale：

logicalHigh_out = logicalHigh_in / q_l

论文逻辑 recombined scale：

logicalRecombined_out = logicalRecombined_in / q_l

其中三个量始终分别处理：

q_l          最后一个 active native modulus
q_div        DCP divisor，已经不在 active basis 中
f_recorded   OpenFHE GetModReduceFactor 返回的 double

补丁没有假设 f_recorded 在数值上一定与 q_l 相同，也没有把两者混为一个变量。

G2 通过先复制项目输入路径消除了对该 clone 行为的输入安全依赖，但 Codex 仍应在 pinned OpenFHE commit 中核验对应 wrapper。

附件中的：

ckksrns-leveledshe.cpp:172-190

明确表明一次 ModReduce 使用：

GetModReduceFactor(sizeQl - 1)

因此本任务的索引就是：

input active tower count - 1

但 GetModReduceFactor 的预计算定义未随包提供，不能额外声称其 double 值必然精确等于 q_l。

3. centered residue 的底层符号细节需要真实源码/执行闭合

dcrtpoly-impl.h:693-712 显示了：

复制最后一塔；

转换为 coefficient；

删除最后一塔；

但附件未包含 native polynomial SwitchModulus 实现和相关 CKKS 预计算定义。因此，精确符号/边界约定仍应由 R2 的 first-principles oracle 在真实 pinned OpenFHE 上闭合。
