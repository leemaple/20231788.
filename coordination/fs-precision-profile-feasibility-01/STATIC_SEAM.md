# Static certificate seam

The user's instruction to decide routine technical questions autonomously is the approval for this bounded internal verification seam; no new user prompt is needed. Under the TDD and codebase-design skills, test the single `certify(profile)` interface used by the command-line certificate emitter. It accepts only the one explicit candidate's immutable scalar data, returns a static analytical certificate, and rejects invalid prime/root/scale data. It is not a public production parameter configuration interface.

Scope: three newly selected exact primes/roots with independently checkable primality witnesses; frozen eight consumed primes and reserved P; all nine exact scales, nominal metadata compatibility, simple terminal capacity ratio, and explicit unresolved precision/security claims. No sampling, encryption, transform, build, network or full-slot replay. A static PASS cannot mean an E80 or security PASS, or prove intermediate nonwrap.

RED first: invoking this interface for the explicit candidate must fail because the implementation does not exist. GREEN then checks the exact static behavior. Follow-up negatives reject corrupted primality witnesses, NTT roots and incoherent initial-scale metadata. These checks are not a substitute for the later production factory RED.
