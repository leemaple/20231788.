# 满槽输入冻结审查

结论：接受以下生成器作为运行前确定性输入域。理想终值非零、约0.1，终态两Base塔的理想编码系数有充足中心余量；槽0/1提供明显超过误差门限的sub-binary64见证。**2^-80是实际运行的验收目标，不是Gaussian噪声所有取值下的保证。**

## 可直接交给实现者的冻结规格

对整数 `s=0..16383`，按如下有理数运算，禁止先转double：

```
t = floor(s/2)
delta = 1/2^75
a = 1015/1024 - (t mod 16)/65536 + s*delta
b = (1 + (floor(t/16) mod 8))/1024
if floor(t/512) mod 2 == 1: b = -b
k = floor(t/128) mod 4
z[s] = i^k * (a + i*b)
expected[s] = z[s]^256
```

四相旋转用分量交换/取负，不算三角函数。独立期望逐槽做8次高精度复数平方；不得调用生产codec/evaluator计算期望。满槽门限冻结为 `max_s(max(|Re(err_s)|,|Im(err_s)|)) <= 2^-80`；codec 160/220两种工作精度的最大分量差 `<=2^-120`。全槽独立oracle使用足够高精度并保留多于120位的可靠余量；可用少量精确有理anchor核验，不必对全槽展开巨大Fraction。现有诊断门限不动。

## 有理界与实际轻量核验

令 `A-=1015/1024−15/65536`，`A+=1015/1024+16383/2^75`。不枚举全槽即可严格有

`L=(A-²+(1/1024)²)^128 <= |expected[s]| <= U=(A+²+(8/1024)²)^128`。

精确有理比较证明 `.098<L<=U<.106<1/4`；十进制展示：L≈0.09837762980994865，U≈0.10518920462622240。真实 `S8/2^100≈1.000364850389603923`，严格介于1与1.000365；`Qbase/2^100≈0.99999999540159657`。

标准满槽CKKS共轭嵌入的归一化逆变换满足每个实多项式系数绝对值≤最大槽模长。因此理想终态系数界 `S8*U < .107*2^100 < Qbase/2`；更紧比例 `2*S8*U/Qbase≈.21045516686478256`。此处只证明理想明文系数；最终加密误差、密钥切换/舍入噪声是否侵蚀余量仍需真实运行。单看中心化解密后系数落在Q/2内不能反证没有回绕，必须检查独立明文误差。

槽0/1的精确有理8平方给出：

```
expected[0] ≈ .1010670169253307545227139032476393
             + i*.0260454205202691164073600171560010
Re(expected[1]-expected[0]) ≈ 6.911041205069354043587716409563219e-22
Im(expected[1]-expected[0]) ≈ 1.773746852731908068554066156036633e-22
```

实部差严格在 `2^-71..2^-70`，约26.10917548×2^-75、835.4936153×2^-80。若binary64先吃掉输入差使两输出相同，至少一个实部误差≥417×门限。甚至最大 `s*delta<2^-61`，小于这些基础实部的半个binary64 ULP `2^-54`，故整个δ序列都不能经binary64输入路径。

观察记录：2026-09-05，在本Mac用 `/usr/bin/python3` 的标准库Fraction做两槽复数幂、两条幅度界和一条S递推；Decimal仅打印65位展示值。一次命令<1秒，无FFT、无密码运算、无全槽Fraction扩展。上述严格不等式均由Fraction比较返回True；展示小数不是冻结常量的替代品。

## 盲点与最小补充控制

`s*delta` 打破同一基础字母在不同s的精确重复；固定槽序的逐槽oracle会拒绝塌缩成重复alphabet。正负b使终值共轭且明显非实，因而普通共轭反转可被识别；全零也必失败。并未据此穷举证明所有不同槽之间的最小距离，勿宣传任意排列均必被门限识别。

确定的代数盲点是 `(i^k*z)^256=z^256`：八平方终值对单槽第四单位根因子不敏感。δ不能修复这种信息丢失。冻结如下控制，均来自**同一条输入密文的八平方链，每host只跑这一条链**：

- fresh阶段生产解码全部16384槽，对原始有理输入逐槽检查最大分量误差≤2^-80，含槽0/1的2^-75输入差；这一步观察fresh输入，不重加密、不另开平方链。
- fresh阶段独立用signed sparse h128秘密做 `c0+c1*s` 的精确整数环运算及CRT，随后在固定槽anchors `{0,1,256,257,512,513,768,769,1023,16383}` 对对应根直接高精度Horner。对原输入核验四相、槽序、共轭方向和sub-binary64见证。秘密仅在客户端oracle中使用。
- 最终阶段生产解码全部槽，对独立 `z^256` oracle检查同一2^-80门限；另用独立sparse/CRT与相同anchors直接Horner核验终值。该oracle须依据实际终态Base前缀和精确S8，不能调用生产FFT/codec。

160/220最大分量差≤2^-120保持独立的codec交叉精度门。两种工作精度一致不能排除共享的排序/归一化错误，Horner anchor不得由同一生产变换自证。最终平方测试不能代替fresh四相控制。上述设计可进入Pro完整编程包；密码噪声、运行资源和实际通过结果尚未测量。
