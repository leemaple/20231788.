## Source-supported conclusions

1. **A fresh full basis `B_i=[A_i,q_div]` is expressible through public APIs.** The ordered `ILDCRTParams` constructor retains input limb order; `CryptoParametersCKKSRNS` exposes constructors and `PrecomputeCRTTables`; the latter consumes the supplied Q. A registered, fully precomputed family whose full Q is `B_i` makes raised-high `B_i` a full basis and low `A_i` its one-limb-short prefix. This removes the specific non-prefix/table-index contradiction in `REPEATED_RELIN2_RAISED_BASIS_REQUIREMENTS.md:17–55`; it does not by itself prove repeated arithmetic. [Ordered constructor][ordered], [public CKKS parameters][params], [table builder][tables].

2. **The proposed family has a concrete table/key-row alignment.** Let `m=|B_i|`, `numPartQ=m`, alpha=1. HYBRID key generation creates m A/B rows, each on `B_i P_i`. High consumes m digits with delta=0; low consumes m−1 digits, keeps Q row positions 0…m−2 and uses delta=1 only for the P columns. Complement tables are selected by actual prefix size and partition. No row from the omitted trailing q_div digit is required by the low path; its high-path row must still exist. These are static consequences of the actual producer/consumer indexing, not runtime observations. [Key generation, lines 54–128][hybridgen], [decomposition, lines 314–378][hybriduse], [row selection, lines 402–434][hybridrows].

3. **Different auxiliary `P_i` are not a cross-family algebraic blocker in this design.** Precompute chooses P locally and skips collisions with that family's Q; its signature has no caller-provided P vector. Each HYBRID invocation uses its evaluation key's own P/tables and mod-down returns to Q_l. If the handoff occurs only after RS2 on A_(i+1), no P-coordinate is transferred. Consequently equal P across families is unnecessary for this particular boundary. Reusing another family's digits, QP rows or P-to-Q tables would invalidate that reasoning. Actual P/QP, row shapes and local mod-down must still be tested. [P selection][pgen], [local mod-down][moddown].

4. **Client-only common-secret projection is source-supported, not automatic.** A fresh `PrivateKeyImpl(ctx_i)` has a fresh tag and accepts an explicitly supplied polynomial. For identical N and matching prime/root/format identities, copying the selected towers of one small signed secret represents the same polynomial in each `B_i`. EvalMultKeyGen forms s² from the supplied s; HYBRID extends that supplied s to the family's P and creates matching rows, rather than resampling it. Thus setup can generate the family and leave evaluation without s. Calling ordinary KeyGen separately per family, or replacing a live secret while retaining its public/evaluation keys, would not establish this relation. If public encryption is exposed in a family, its public key must also match that projected secret and the explicitly chosen public-key basis. [Fresh private object/setter][private], [s² generation][squarekey], [HYBRID secret extension][hybridgen], [ordinary sampling/keypair][keygen].

## Important qualifications / incorrect interpretations to reject

- **alpha=1 is not literally numPartQ=11 at every fresh context.** The table builder computes `alpha=ceil(m/numPartQ)` and rejects `m<=alpha*(numPartQ−1)`. Setting numPartQ=m passes for nonempty m and preserves one prime per digit; setting 11 on a fresh m≤10 basis fails. For the supplied paper 11-limb starting vector, this can be described as initial dnum=11 with only nonempty singleton digits retained in smaller families. It cannot be described as every family retaining the same parameter value, evaluation key, noise distribution or performance. Paper equivalence of the resulting related key family remains an explicit design/empirical claim, not a consequence of alpha alone. [Actual guard][tables]; `PAPER_ORDERED_Q_PUBLIC_CONTEXT_SUPPORT.md:57–64`; task `REPEATED_MULT2_PRO_DESIGN_AND_TDD.md:72–80`.
- **“Copy and bind” requires construction, not an ordinary clone.** `CiphertextImpl(nextCtx,nextTag,encoding)` plus `SetElements` is public; copy constructors preserve the old CryptoObject/context. Rebinding leaves `c0+c1*s` unchanged only after the same-secret and exact active-basis relationship has been established. Set elements before SetLevel; for active A_(i+1) under full `[A_(i+1),q_div]`, the relative prefix level is 1, not the old family's level 2 or a generic 0. Preserve/validate slots, encoding, degree and scale deliberately. [Ciphertext constructors/elements][ciphertext], [level setter][level].
- **Tags and wrappers do not prove family correctness.** EvalMultKeyGen skips tags already in its static map; Relinearize looks up by ciphertext tag and checks null/row count, not the complete context/basis correspondence. Require distinct family key identities and explicit context, ordered Q/P/QP and row validation. Factory registration can reuse equivalent contexts; immutable means an application discipline, not an upstream type guarantee. Select `SetKeySwitchingTechnique(HYBRID)` explicitly: enabling KEYSWITCH alone does not construct it. [Key cache][cache], [Relinearize wrapper][relinwrapper], [factory][factory], [scheme selection][scheme], [enablement][enable].
- **N=256 normal sparse h=192 is a valid source-predicted probe distinction, not h128 acceptance.** Ordinary sparse KeyGen passes 192 to the sampler; the clamp does not reduce it at N=256. Explicit low-level h128 sampling is a separate route with its own matching-key checks and sign-distribution qualification. The normal sparse probe cannot be relabeled as the paper's N=32768,h128 experiment. [Sampling][keygen], [sampler][sampler]; `PAPER_H128_OFFICIAL_API_SUPPORT.md:38–42,85–97`.

## Still requires the returned code and hosted evidence

The visible family mechanism has **no identified deterministic public-API/table-index impossibility** after the above qualifications. No implementation correctness claim follows. Next inspection must verify fresh parameter/scheme construction, explicit PREMode/noiseScale/configuration, factory/tag ownership, actual per-level rows/bases, unchanged inputs/contexts/keys, and evaluation with no secret access. Fresh wrappers do not fix scale arithmetic: FIXEDMANUAL uses actual trailing-prime tables but metadata divides by 2^p. Freeze and verify exact logical scale progression, including the project-described `S_(i+1)=S_i²/(q_div*q_l,i)`, separately from component metadata and decoder behavior. [Actual rescaling][rescale], [constant metadata factor][factor].

Then obtain independent second-Mult2 arithmetic and precision evidence, followed by the specified asymmetric 40/60 chain, eight squarings and separate paper N/h128/dnum/P/trial requirements. The visible design and any low-N routing probe do not satisfy those results. No new all-key theorem completion gate is introduced.
