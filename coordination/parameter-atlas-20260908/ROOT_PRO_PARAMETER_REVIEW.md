1. **Current source requests two OpenMP threads for all three named profiles, although historical effective execution remains unverified.** `PARAMETERS.json:build.threads` and the main table report the explicit `OMP_NUM_THREADS=2` request only for S100-annulus125 and leave S100-original/S116 as merely unconfirmed. The uncertainty about an old binary/run is correct, but the current source request is independently visible for the original S100 contract and S116 contract as well: `project/CMakeLists.txt:set_tests_properties:266-301` sets `ENVIRONMENT "OMP_NUM_THREADS=2"`; additional named test properties do so at `326-354`; `project/.github/workflows/dcp-rcb.yml:202-266` supplies the same workflow request. Recommended distinction: **requested/source value = 2 for S100, S116, and annulus; effective historical team size and compiled OpenMP branch = pending**.
2. **The machine dictionary has no dedicated `familyCount` / `familyQCount` records.** The facts are present indirectly (`basis.partition_count`, `key.evalkey_family`, and main §3.2), so this is not a main-document factual gap, but a machine consumer cannot address those two project state knobs directly. The explicit values are `familyCount=8` and full family Q counts `11-f` for `f=0..7`; active pair sizes are `10-f` before RS2 and `9-f` after RS2 (`project/src/repeated_mult2.cpp:RepeatedMult2Plan::RepeatedMult2Plan:257-310`; `project/src/double_ckks.cpp:DoubleCKKS::DCP/RS2:440-462,1080-1210`). Adding aliases/records would make change-coupling checks less dependent on prose.
3. **Known fixed-anchor label typo:** raw Pro references label `project/src/paper_h128_client_keypair.cpp:193-217` as `CreatePaperH128ClientKeyPair`; the source function is `CreateFixedQH128ClientKeyPair`. The path and line range identify the right code, so values derived from the range are not changed (`project/src/paper_h128_client_keypair.cpp:CreateFixedQH128ClientKeyPair:193-217`).
