# C7 controlled cost preparation

Source base53f78f892edee6987c4439d3fd1179497bab7a65; arithmetic implementation93f128b is unchanged. This step prepares engineering artifacts only. Public GitHub CI is never a scientific timing source.

1. Add an opt-in static-OpenFHE build for portable macOS arm64 CLI binaries. The default shared build remains intact. Pristine OpenFHE1.5.0 pin df495ba2e91739a6dc8f1de254fc5a41155ce504, native64/backend4, OpenMP OFF, native CPU tuning OFF, deployment target15.0. Transport binaries must depend only on Apple system libraries. Build on standard public macos-15 arm64, maximum2 compiler workers and25 minutes; never build OpenFHE on the user's Mac in this step.
2. The standalone c7_cost_probe has check-only mode and separately gated study mode. Check-only uses N32,30/35-bit moduli, HYBRID, no security-level claim. It must compare Reference/Reordered/Fused for RS2 and the full Tensor2→Relin2→RS2 composition against the unchanged public Mult2 result on exactly the same encrypted inputs. Compare all native values and state; deliberately corrupted coefficient and slot metadata must be rejected by the comparator. Inputs must be unchanged. Existing rs2_test covers detailed metadata provenance, aliases, invalid states and full-integer CRT/rescale oracle. Re-run its21 green checks on the new platform; retain the original witnessed red/green history rather than inventing a new arithmetic change.
3. CI runs check-only, the existing21 functional checks and API signature test. Never invoke --study in CI. Preserve source/compiler/OS/OpenFHE identities, logs, checks and binary SHA256. A failed/partial/missing receipt cannot pass. One evidence-driven build repair is allowed under the registered outer budget; no preferred-outcome rerun.
4. Prospective study parameters (not authorized by this engineering step): N16384/32768, depth3, first modulus60 bits, subsequent58 bits, full N/2 slots, FIXEDMANUAL, HYBRID, HEStd_128_classic with OpenFHE's default uniform-ternary secret. This is not the paper's h128 sparse-key or S100 precision experiment. Each size uses one generated key family and one fixed complex input pair; same exact ciphertexts/keys are shared across backends. No secret/evaluation keys are exported. Public pair data are archived as documented little-endian uint64 residues; exact key-specific replay is not promised because keys are not exported.
5. Timing boundaries: RS2 with all existing validation, and complete Tensor2→Relin2→RS2 including intermediate allocation/destruction and validation. Returned output remains live at timer stop; caller destruction and equality comparison are outside. Shared key generation, encryption, DCP, one-time reference generation, verification, public-input export and warmups are reported together as one-time preparation (not a pure keygen/setup measurement). Each call is checked against the full Reference result outside its timer. No source validation is removed.
6. Prescribed study order: both sizes ascending; six balanced backend permutations; alternating stage order by block; four calls per backend/stage/block. All288 raw wall/process-CPU records must be retained, without outlier deletion or best-of selection. No cross-run parameter tuning. This is a first diagnostic, not a formal experiment; additional large or repeated-multiplication campaigns require a new contract. No native timings are authorized here.
7. The first value decision will use whole RS2 and whole Mult2 boundaries. Kernel-only attribution is deferred until an actual increment survives the stronger ordinary-reordered baseline. This avoids instrumenting an unpromising candidate while keeping complete cost as the decisive question. Formal claims still need novelty, meaningful effect, source/parameter coverage and evidence admission.
