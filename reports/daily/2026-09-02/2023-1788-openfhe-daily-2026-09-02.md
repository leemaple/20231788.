## 3. 已完成的工作

### Relin2 已接受的绿边界

1. 公共 API scaffold；
2. Tensor 输入校验必须先于键查询；
3. 活动 Q_l 塔数不得小于 Tensor noise-scale degree；
4. 指定 key tag 的 relinearization key 必须存在；
5. evaluation-key vector 不得为空；
6. 第一把 key 不得为 null；
7. 第一把 key 必须属于当前 CryptoContext；
8. 第一把 key tag 必须匹配 Tensor key tag；
9. 第一把 key 必须是正确的 `EvalKeyRelinImpl` 子类型；
10. HYBRID A、B vector 的长度必须分别匹配 `GetNumPartQ()`。

这些边界均按“测试先红、最小生产修改变绿、小 commit、立即 push、保留 CI 证据”的顺序完成。最近接受的 Hosted run 为 `33574998256`，对应 `0e240f3...`，Relin2 相关总测试为 16/16。

### 最新红边界

第 17 项测试针对 HYBRID evaluation key 的每个 A/B 条目完整 `ParamsQP` 有序基底：

- 正控使用独立分配的 aggregate 参数和每个 NativePoly tower 参数，但全部语义值相等，防止实现错误地比较指针身份；
- 负控只交换 `B.back()` 的前两座完整塔，保持长度、格式、上下文、tag、子类型、塔数和其余条目不变；

## 5. 关键难点、已解决问题与剩余风险

| 难点 | 原因 | 处理/解决方案 | 状态 |
|---|---|---|---|
| 旧实现已知错误且不得复用 | 复用会污染 clean-room 结论 | 独立仓库、分支和工作树；只从可信 Tensor2 基线前进 | 已控制 |
| eval key 基底可能出现“指针不同但语义相同” | 只比较参数指针会拒绝合法 key，浅正控会让测试假绿 | 深克隆 aggregate 与每座 tower 参数并验证全值等价；负控只改变有序基底 | 测试已解决，生产绿待写 |
| 负例容易被更早 guard 截获 | 错误的 fixture 会证明错误边界 | 每个负例冻结非目标字段，并要求精确异常类型与完整诊断字符串 | 已持续执行 |
| 跨平台 OpenFHE 构建较重 | Mac 本地重编译会卡顿；Windows 构建延迟大 | 使用 GitHub Actions 的 Linux/Windows exact-SHA CI；Mac 只做轻量静态检查 | 已控制 |
| Relin2/RS2 的 scale 与生命周期 | 论文 logical scale、OpenFHE recorded scale、FIXEDMANUAL tower drop 语义不同 | 已冻结双尺度契约；后续每步用独立 oracle 与生命周期表约束 | 关键剩余风险 |
| 外部 Agent/额度可用性 | ZCode 周额度耗尽，模型长思考可能拖慢 | ZCode 移出关键路径；难题及时问 Fable 5.1，失败/无结果即记录并继续；GitHub Actions 承担持续测试 | 不阻塞 |
